# TeamProject Manager

## Назначение
Приложение для управления командными проектами. Позволяет создавать проекты, назначать команды, ставить задачи и отслеживать их выполнение.

## Целевая аудитория
Руководители команд, тимлиды, участники проектных групп, желающие структурировать работу над проектами.

## Описание предметной области
Управление проектами (Project Management). Основные процессы: создание проекта, формирование команды, постановка и распределение задач, контроль статуса выполнения.

## Основные классы

### Project
Проект, которым управляет команда.
- **Атрибуты**: `name`, `description`, `manager`, `start_date`, `end_date`, `status`.
- **Методы**: `is_active()` — проверка активности проекта; `get_info_text()` — текстовое описание проекта; `__str__()` — краткое строковое представление (название и статус).

### Member
Участник команды проекта.
- **Атрибуты**: `name`, `role`.
- **Методы**: `__str__()` — строковое представление участника («Имя - Роль»).

### Task
Задача проекта.
- **Атрибуты**: `name`, `status`, `assignee` (объект `Member`, ответственный за задачу).
- **Методы**: `is_completed()` — проверка выполнения задачи; `get_status_text()` — статус в читаемом виде; `__str__()` — строковое представление задачи.

## Взаимодействие объектов
Объект `Task` хранит прямую ссылку на объект `Member` в атрибуте `assignee` (а не просто имя строкой). Это позволяет обращаться к данным участника через связанный объект задачи, например `task.assignee.name`. Проект (`Project`) существует независимо и напрямую не хранит ссылки на объекты `Member`/`Task` — они передаются в приложение отдельными коллекциями.

## Основные функции
- Создание нового проекта.
- Добавление участников в команду проекта (`add_member`).
- Поиск участников по имени (`find_member`).
- Создание и назначение задач по проекту (`add_task`).
- Отображение списка проектов с их статусами.
- Просмотр списка задач по проекту.
- Расчёт прогресса выполнения проекта (`calculate_progress`).

## Структура проекта
- `main.py` — точка запуска, меню приложения;
- `models/` — пакет с классами предметной области:
  - `project.py` — класс `Project`;
  - `member.py` — класс `Member`;
  - `task.py` — класс `Task`;
- `projects.py` — функции работы с участниками (`add_member`, `find_member`);
- `tasks.py` — функции работы с коллекцией задач (`add_task`, `count_completed_tasks`, `calculate_progress`, `filter_tasks_by_status`, `sort_tasks_by_status`);
- `storage.py` — загрузка и сохранение объектов в JSON;
- `utils.py` — вспомогательные функции безопасного ввода;
- `data/` — файлы данных проекта (`projects.json`, `tasks.json`);
- `tests/` — автоматизированные тесты.

## Формат хранения данных
Данные по-прежнему хранятся в формате JSON: `data/projects.json` (проект и участники) и `data/tasks.json` (задачи). При загрузке JSON преобразуется в объекты `Project`, `Member` и `Task`; при сохранении объекты преобразуются обратно в JSON (связь `Task.assignee` сохраняется как имя участника).

## План развития проекта

- разработка веб-приложения на Django;
- подключение базы данных (SQLite/PostgreSQL);
- реализация аутентификации пользователей;

- контейнеризация приложения с помощью Docker;
- настройка CI/CD.
